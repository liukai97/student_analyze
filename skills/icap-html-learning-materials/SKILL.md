# ICAP HTML 学习材料

## 目标

把学习证据或教学目标转化为学生可直接使用的 HTML 学习材料。最终产物应让学生经历“注意与提取 → 操作与辨析 → 生成解释 → 组织关系 → 独立迁移”，并能外显地构建、检验和修正自己的 schema（知识结构），而不只是阅读讲解或完成选择题。

本技能适用于各学科。保留学科事实、符号、论证规范和年龄难度，不套用某一门学科的固定知识点或题型。

## 交付边界

- 最终成品默认不发布、不部署、不上传；交付可由学生在本地手动打开的 HTML。
- 制作过程中可临时启动本地预览服务，让用户实时查看并对页面元素添加注释。完成后关闭为本任务启动的服务，除非用户明确要求保留。
- 不生成分享预览图、Open Graph 图、社交封面或营销缩略图，除非用户明确要求。教学内容本身需要的图示、示意图或图片不受此限制。
- 内容较少、资源简单时，优先交付一个自包含 `.html` 文件。内容较多或含较多图片、音频、数据等资源时，交付一个目录，其中以 `index.html` 为入口，并使用可移植的相对路径。
- 无论单文件还是目录，最终版本都不得依赖开发服务器。默认避免 CDN、在线字体、远程接口和运行时下载，使材料在 `file://` 下可用；若用户允许联网依赖，应明确说明。
- 不因为使用交互网页就扩展为账号、后端、云存储、班级管理或数据上报系统，除非用户要求。

## ICAP 方法论

用认知活动而非界面动作判断层级：

- **Passive（被动）**：接收或浏览信息，如阅读、观看、听讲。用于建立共同背景，篇幅应克制。
- **Active（主动）**：对材料进行可观察的操作，如标注、排序、匹配、选择、圈画、拖放或提取关键信息。操作必须服务于注意和辨析；“点了按钮”本身不代表有效主动学习。
- **Constructive（构建）**：学生产出超出所给材料的内容，如自我解释、推断原因、预测结果、补全关系、提出例子、画概念图、比较模型或设计解法。文本框本身不代表构建；任务必须要求新关系或新解释。
- **Interactive（交互）**：两个或更多学习者通过对话互相回应、追问、修正并共同生成理解。人与页面的点击交互不等同于 ICAP 的 Interactive。只有真实存在同伴、教师或可持续回应的对话主体时才这样标注。

目标通常是让学生达到 **Constructive**。可以用 P 和 A 降低进入门槛，再通过生成、解释和迁移进入 C；不要为了形式完整而强制加入 I。若安排同伴活动，应要求双方在彼此观点上继续构建，而不是简单轮流作答。

## 从证据选择教学切入口

1. 完整阅读用户指定的报告、学生作答、课程目标或参考材料，区分直接证据、分析推断和未知信息。
2. 提取学生已有能力、稳定错误、缺失连接、先备知识与可能的迁移情境。不要仅凭一次错误断言长期薄弱。
3. 候选知识点按以下标准选择切入口：
   - 能解释多种错误或带动多个后续任务；
   - 位于关键先备关系或概念网络的枢纽；
   - 有足够证据支持，且能设计可观察的学习表现；
   - 难度适合通过若干脚手架进入，而非只能背结论；
   - 能迁移到新题、新情境或新表征。
4. 明确说明为何选择该切入口、证据是什么、哪些判断仍是假设。若用户只要求分析和计划，在此阶段停止，不提前生成成品。
5. 先定义最终 schema：核心概念或步骤、它们之间的关系、成立条件、边界或例外、常见混淆，以及学生需要完成的迁移表现。

## 设计学习路径

围绕一个完整学习闭环组织材料，不必机械使用固定页面结构：

1. **低威胁诊断**：用少量任务区分概念缺失、关系混淆、程序错误和表征困难。先让学生作答，再提供反馈；诊断结果应能改变提示或学习建议。
2. **最小讲解**：提供完成下一步所需的概念、范例或方法。把专家思路外显，但不要一次性给出整套答案。
3. **主动辨析**：让学生标记关键信息、比较案例、排序步骤、分类表征或选择证据，并说明操作目的。
4. **引导构建**：让学生补全因果链、关系句、概念图、解释模板、预测或解题计划。先给结构性提示，再逐渐撤除。
5. **独立构建**：面对变化后的材料，学生自行生成解释、结构或方案；不要把答案拆成可猜的选择项。
6. **校验与修正**：要求学生用证据、条件、反例、单位、边界情况或另一种表征检查产出。反馈应解释为什么，并允许修改后重试。
7. **迁移退出任务**：使用表面不同但深层结构相同的新情境，要求学生重建而非复述。让学生说明哪些关系可迁移、哪些条件发生了变化。
8. **schema 外显**：结尾让学生产出可检查的网络，例如“节点—关系—条件—例证/反例”图、规则表、流程图或自己的判断清单。

每个主要任务都应能回答：学生必须产出什么？该产出如何显示其认知层级？反馈如何帮助其修正 schema？

## 辅导文本与练习原则

- 语言、符号和任务长度匹配目标学段；先用学生可理解的表述，再引入必要术语。
- 例题展示决策依据和关系，不只展示步骤。区分“观察到什么”“由此推出什么”“还需验证什么”。
- 练习按认知跨度递进，而不是只增加数字、篇幅或计算量。推荐梯度为：识别 → 比较/分类 → 补全解释 → 多表征连接 → 独立生成 → 迁移与反思。
- 同一关键关系至少在两种表征或情境中出现，帮助学生识别深层结构；避免大量同构刷题造成熟练假象。
- 干扰项来自真实误概念，并在反馈中指出错误关系；不要用措辞陷阱测阅读猜测。
- 提示分层提供：关注点 → 关系提示 → 部分结构 → 完整讲解。默认不要在第一次尝试前暴露答案。
- 反馈同时包含结果、理由和下一步；对开放任务提供判据、自检清单、样例结构或可比较的参考答案，而非假装能可靠自动评分所有自由文本。
- 逐步撤除句式框架、节点候选、步骤卡片和高亮线索，使最后的迁移任务由学生独立完成。
- 控制无关装饰和操作负担。动画、拖拽或游戏化只有在帮助比较、排序、观察变化或建立关系时才使用。

## 学科表征与图形化

- 当空间关系、连接关系、过程变化或多变量关系用图形比纯文本更清楚时，选择性使用学科原生图示；不要为了美观把所有符号内容图片化。
- 保留学生需要掌握和书写的符号形式，并让图形与符号、语言或数据相互对应。图形用于显化关系，不替代必要的公式、方程式、结构简式、代码或文字论证。
- 优先使用确定性、可校验的矢量图、图表或学科工具输出。需要逐个元素准确的图示不得依赖生成式图片的视觉可信度。
- 制作化学学习材料时，读取 [references/chemistry.md](references/chemistry.md)。化学结构、官能团、反应结构变化、键线式和相关练习必须遵循其中的化学专用规则。

## HTML 实现

- 先建立清晰的信息结构和无 JavaScript 时仍可阅读的核心内容，再加入真正服务学习任务的交互。
- 使用语义化 HTML、可见焦点、键盘可操作控件、明确标签、足够对比度和适合学生设备的响应式布局。
- 学习状态可用 `localStorage` 保存，并提供“重置进度”。不要收集或传输学生数据，除非用户明确授权并给出边界。
- 直接打开目录版本时，不要依赖通过 `fetch()` 读取本地 JSON 等常被 `file://` 安全策略阻止的机制；可将必要数据嵌入脚本或在构建时打包。
- 图像应有替代文本；关键含义不能只靠颜色表达。化学式、数学式、代码、谱图、地图等学科表征应保持准确且可读。
- 若使用构建工具，最终仍需生成可直接手动打开的静态产物，并把入口与所需资源完整交付。

## 验证与交付

1. 校验学科事实、答案、推理链、难度梯度和反馈一致性；不确定内容要标明或回到来源核对。
2. 检查所有核心任务是否真正要求生成新解释或新关系，并至少包含一个独立迁移任务和一个 schema 外显产物。
3. 从首次学习者视角完成一次主路径，验证提示、重试、答案揭示、进度、重置和打印等已实现功能。
4. 直接以本地文件方式打开最终入口，检查无开发服务器时的脚本、样式、媒体和相对路径。测试窄屏与常见桌面宽度，并检查浏览器控制台错误。
5. 若启动过本地预览服务，交付前将其关闭并确认相关端口不再监听。
6. 最终告知用户：入口文件的绝对路径、单文件还是目录、是否有外部依赖、完成了哪些验证。不要附发布链接，也不要主动创建分享预览图。
